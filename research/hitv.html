ANALYSIS: hiTV APP

Subject: Reverse Engineering & Deconstruction

01_المقدمة (Summary)

هذا البحث يستعرض نتائج الهندسة العكسية لتطبيق hiTV. تم التركيز على فهم طريقة عمل البرنامج، البحث على كل الاكواد الخبيثة فالبرنامج ، معرفة اين يتم ارسال البيانات المسروقة من الهاتف. الهدف هو كشف اي التهديدات في البرنامج.

03_النتائج التقنية (Findings)

بعد تحليل ال Apk لقينا هاذي الاكواد الخبيثة:

1

/* JADX INFO: loaded from: assets/lspatch/loader.dex */
public class Application implements Parcelable {
    public static final Parcelable.Creator<Application> CREATOR = new Parcelable.Creator<Application>() {
        @Override
        public Application createFromParcel(Parcel parcel) {
            Application application = new Application();
            application.readFromParcel(parcel);
            return application;
        }
    };

هذا الكود هو جزء من نظام LSPatch، ومهمته الأساسية هي تعريف الهدف المراد اختراقه حيث يقوم باستخدام واجهة Parcelable لنقل بيانات التطبيق مثل اسم الحزمة ومعرف المستخدم ملف خارجي مخفي داخل الـ إلى ذاكرة النظام . يكمن خبث هذا الكود في أنه يمثل جسر العبور الذي يسمح بحقن كود خارجي Hooking داخل عمليات تطبيقات أخرى دون علم المستخدم، مما يمنح المهاجم القدرة على اعتراض كلمات المرور، قراءة الرسائل، أو تزييف واجهات التطبيقات البنكية عبر السيطرة الكاملة على الدوال Methods داخل بيئة الـ Runtime، وكل ذلك يتم دون الحاجة لصلاحيات الروت التقليدية، مما يجعله وسيلة احترافية للتجسس وتجاوز حماية أندرويد.

04_المخاطر المكتشفة

[CRITICAL]

خطف الأوامر

يسمح للمخترق بتغيير أي شيء، مثل تحويل مبلغ مالي من تطبيق بنكي دون علمك.

[MEDIUM]

تشفير البيانات

يستخدم لإخفاء روابط السيرفرات التي تستقبل بياناتك المسروقة بعيداً عن أعين الحمايات والمستخدمين.

[CRITICAL]

تجاوز البصمة/القفل

القدرة على فتح التطبيقات المقفلة أو قفل الشاشة عبر تزييف نتيجة التحقق.

[Hard]

سحب البيانات

سرقة سجل المكالمات، الرسائل النصية SMS، وقائمة الأسماء بالكامل.

[Hard]

حقن الكود LSPatch

يجعل التطبيق يختبئ داخل تطبيقات نظامية أخرى، مما يصعب حذفه أو اكتشافه.
